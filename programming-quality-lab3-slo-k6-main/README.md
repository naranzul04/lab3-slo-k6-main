# Лаборатори №3: Чанарын сценарио → SLO → k6 threshold

А.Наранзул — B222270823

* Хичээл: F.CSA313 — Программ хангамжийн чанарын баталгаа ба тест
* k6 хувилбар: `k6.exe v2.2.0 (commit/00a9a1b7f5, go1.26.5, windows/amd64)`

Энэхүү лабораторийн ажилд зөвхөн локал Express API дээр k6 ашиглан ачааллын туршилт хийсэн бөгөөд гадаад систем рүү ямар нэгэн хүсэлт илгээгээгүй.

## Локал API

```bash
npm install
npm start

```

Сервер нь `http://localhost:3000` хаяг дээр ажиллана. Эдгээрээс `/cart/add` түргэн хариу өгдөг, `/report` нь 200–400 мс-ийн сааталтай, харин `/pay` нь ойролцоогоор 5% магадлалтайгаар HTTP 500 алдаа буцаадаг.

## Чанарын сценарио

| Хэсэг | Performance | Reliability | Availability |

| Системийн төлөв | API хэвийн ажиллаж, өгөгдлийн сангийн нэмэлт сааталгүй байна | API хэвийн ажиллаж, gateway-ийн санамсаргүй алдаа идэвхтэй байна | API 2 минутын турш ачаалал авч байна |
| Орчны төлөв | Локал машин дээр 20 VU тогтмол ачаалал өгнө | Локал машин дээр 20 VU төлбөрийн хүсэлт илгээнэ | 20 VU гурван endpoint рүү хүсэлт илгээнэ |
| Гадаад өдөөлт | Хэрэглэгч `/cart/add` руу POST хүсэлт илгээнэ | Хэрэглэгч `/pay` руу POST хүсэлт илгээнэ | Тестийн дунд Node.js серверийг 10 секунд зогсоогоод дахин асаана |

## SLO

| Сценарио | SLI | Босго | Цонх / нөхцөл |
| --- | --- | --- | --- |
| Performance | `/cart/add` latency | p95 < 10 мс | 20 VU, 1 минут |
| Reliability | `/pay` error rate | < 8% | 20 VU, 1 минут |
| Availability | бүх endpoint-ийн check амжилт | > 90% | 20 VU, 2 минут, 10 секундийн зогсолттой |
| Нэмэлт performance | `/report` latency | p95 < 450 мс | 20 VU, 1 минут |

`/cart/add` нь локал орчинд ажилладаг хөнгөн endpoint тул p95 босгыг 10 мс гэж тогтоосон. `/pay` дээр 5% санамсаргүй алдаа үүсдэг учир түүвэрлэлтийн хэлбэлзлийг тооцон 8% босго тавьсан нь зохимжтой. `/report` нь 200–400 мс хүлээдэг тул 450 мс нь хэвийн саатлыг багтаах боловч хэт өндөр биш хязгаар юм. Availability SLO 90% байгаа тул 2 минутын хугацаанд зөвшөөрөгдөх хугацаан дээр суурилсан error budget нь `120 × 0.10 = 12 секунд` байна.

## Туршилт ажиллуулах

PowerShell дээр хоёр тусдаа терминал нээж PASS болон зориуд FAIL хийлгэх тестүүдийг ажиллуулна.

```powershell
# Терминал 1
npm start

# Терминал 2
k6 run --no-color slo-test.js 2>&1 | Tee-Object results/pass.txt
k6 run --no-color slo-test-fail.js 2>&1 | Tee-Object results/fail.txt

```

Chaos сценарийн controller нь серверийг эхлүүлж, 30 дахь секундэд унтраагаад 10 секундийн дараа буцааж асаана. Зогсолт болон дахин асгах цагийн тэмдэглэл, нийт outage хугацаа `results/chaos.txt` файлд хадгалагдана.

```powershell
node scripts/run-chaos.js

```

## Үр дүн

| Туршилт | Хэмжсэн утга | Босго | Үр дүн |
| --- | --- | --- | --- |
| PASS — `/cart/add` p95 | 1.99 мс | < 10 мс | PASS |
| PASS — `/report` p95 | 395.74 мс | < 450 мс | PASS |
| PASS — `/pay` error rate | 5.63% | < 8% | PASS |
| PASS — нийт checks | 98.12% | > 90% | PASS |
| Chaos — availability | 87.75% | > 90% | FAIL |
| Chaos — `/pay` error rate | 15.36% | < 8% | FAIL |
| Зориудын FAIL — `/report` p95 | 397.27 мс | < 100 мс | FAIL |

PASS туршилтын exit code `0`, харин зориуд унагасан FAIL туршилтынх `99` гарсан. Дэлгэрэнгүй лог нь [results/pass.txt](https://www.google.com/search?q=results/pass.txt), [results/chaos.txt](https://www.google.com/search?q=results/chaos.txt), [results/fail.txt](https://www.google.com/search?q=results/fail.txt) файлуудад бичигдсэн.

### Chaos ба error budget

Controller-ийн бүртгэсэн бодит зогсолтын хугацаа `10.021 секунд` байв. Хүсэлт бүрд нэг check ажилласан тул хүсэлтийн тоогоор бодсон availability `4968 / 5661 × 100 = 87.75%` болсон. 90% SLO-ийн хүрээнд зөвшөөрөгдөх алдаатай хүсэлтийн дээд хэмжээ `5661 × 10% = 566.1` байсан ч бодит алдаа `693` гарч, хүлээн зөвшөөрөгдөх хэмжээнээс `126.9` хүсэлтээр давжээ. Өөрөөр хэлбэл, хугацаагаар тооцсон 12 секундийн error budget дотор багтсан ч хүсэлтийн тоогоор тооцсон budget хэтэрсэн байна.

## Дүгнэлт

Чанарын шаардлагыг SLO болгон томьёолж, улмаар k6-ийн threshold болгон буулгахад хэмжилтийн нэгжүүдийг (хугацаа, хувь, хүсэлтийн тоо) зөрүүлэлгүй уялдуулах нь гол сорилт байлаа. Хэвийн ажиллагааны туршилтаар `/cart/add`-ийн p95 нь 1.99 мс гарч 10 мс-ийн босгыг хангаснаар performance зорилт биелсэн. `/pay` endpoint-ийн алдааны хувь 5.63% гарсан нь кодын 5%-ийн санамсаргүй алдаатай нийцэж, 8%-ийн reliability хязгаарт багтсан. Мөн `/report`-ийн p95 нь 395.74 мс байсан нь 450 мс-ийн босго бодит ачааллын төлөвийг оновчтой тусгаж байгааг харуулав. Харин chaos туршилтын үед availability 87.75% болж унасан нь 90% хүрнэ гэсэн урьдчилсан таамагтай зөрсөн. Зогсолт 10.021 секунд үргэлжилж цагийн 12 секундийн budget-д багтсан хэдий ч сервер унтарсан үед маш хурдан тасарсан connection-refused хүсэлтүүд олноор хуримтлагдан request budget-ийг давуулжээ. Үүний зэрэгцээ сервер зогсох үед `/pay` хүсэлтүүд ч тасалдсанаас reliability үзүүлэлт 15.36% болж хамт унасан. Тиймээс серверээс ирсэн жинхэнэ HTTP 500 алдааг тусгай custom metric-ээр, сүлжээ/холболтын тасалдлыг availability metric-ээр ялгаж хэмжих нь илүү нарийвчлалтай болгоно. Зориудын FAIL тестэд `/report`-ийн p95 397.27 мс байхад 100 мс threshold зөрчигдөж exit code 99 буцсан нь threshold тохиргоо автомат шалгалтын үед доголдол илрүүлэхэд хэрхэн ажилладгийг бодитоор баталлаа.
